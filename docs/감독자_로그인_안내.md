# 감독자 로그인 안내

이 문서는 회중에서 임명받은 감독자와 담당자가 편집자 화면에 로그인하는 기본 방법을 설명합니다.

## 1. 로그인 주소

설치가 완료되면 편집자 화면은 아래 주소로 접속합니다.

```text
https://YOUR_PAGES_DOMAIN/admin.html
```

예를 들어 Cloudflare Pages 주소가 `example.pages.dev`라면 다음과 같습니다.

```text
https://example.pages.dev/admin.html
```

## 2. 기본 로그인 방식

이 프로그램은 역할별 PIN 로그인 방식을 사용합니다.

초기 역할과 PIN은 아래 파일에서 설정합니다.

```text
templates/roles.csv
```

설치 담당자는 이 파일을 자기 회중 상황에 맞게 수정한 뒤 초기 설정 스크립트를 실행합니다.

```powershell
node scripts/setup-from-csv.mjs
```

## 3. 기본 역할 예시

배포본에는 예시 역할이 들어 있습니다.

| 역할 | 예시 PIN | 기본 권한 |
| --- | --- | --- |
| 서기 | 2468 | 전체 보고 확인, 성원 명단, 광고 관리 |
| 봉사 감독자 | 1357 | 전체 보고 확인, 봉사 관련 안내 관리 |
| 1집단 감독자 | 1111 | 1집단 관련 자료 관리 |
| 2집단 감독자 | 2222 | 2집단 관련 자료 관리 |

위 PIN은 예시입니다. 실제 사용 전 반드시 변경하세요.

## 4. 역할 추가 방법

`templates/roles.csv`에 줄을 추가하면 새 담당자 역할을 만들 수 있습니다.

예:

```csv
group3-overseer,3집단 감독자,3333,editor,group3,groupnews,false,false,false,true,true
```

주요 항목:

- `key`: 역할 고유값입니다.
- `name`: 화면에 표시될 역할 이름입니다.
- `pin`: 로그인 PIN입니다.
- `groupKeys`: 관리할 집단입니다. 예: `group1`, `group2`, 전체는 `*`
- `noticeKeys`: 관리할 광고 메뉴입니다. 여러 개는 `|`로 구분합니다.

## 5. 권한 설명

`roles.csv`의 권한 항목은 `true` 또는 `false`로 설정합니다.

- `canReadCongReports`: 회중 전체 보고 집계 확인
- `canWriteCongMembers`: 성원 명단 수정
- `canManagePublications`: 출판물 배부 관리
- `canReadContacts`: 연락처 확인
- `canWriteContacts`: 연락처 수정

## 6. 설치 후 반드시 할 일

1. 예시 PIN을 실제 PIN으로 변경합니다.
2. 필요 없는 예시 역할을 삭제합니다.
3. 각 집단 감독자에게 자기 역할의 PIN만 전달합니다.
4. 담당자가 바뀌면 해당 PIN을 변경합니다.
5. PIN을 카페, 공개 GitHub, 단체 채팅방에 올리지 않습니다.

## 7. PIN을 바꾼 뒤 적용하는 방법

`templates/roles.csv`를 수정한 뒤 다시 실행합니다.

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS="C:\path\firebase-service-account.json"
$env:FIREBASE_PROJECT_ID="YOUR_FIREBASE_PROJECT_ID"
$env:CONG_NAME="○○회중"
node scripts/setup-from-csv.mjs
```

실행 후 새 PIN으로 편집자 화면에 로그인되는지 확인합니다.

## 8. 로그인 문제 해결

PIN 로그인이 되지 않으면 아래 내용을 확인하세요.

- `roles.csv`에 해당 역할이 있는지 확인합니다.
- PIN 숫자가 정확한지 확인합니다.
- `node scripts/setup-from-csv.mjs`를 다시 실행했는지 확인합니다.
- Worker의 `FIREBASE_SERVICE_ACCOUNT` secret이 설정되어 있는지 확인합니다.
- `web/.env`의 `VITE_WORKER_URL`이 실제 Worker 주소와 맞는지 확인합니다.
