Firebase 값 입력 화면

Firebase 설정값은 복사해서 붙여 넣기

Firebase 콘솔에서 웹 앱을 등록하면 아래 값을 확인할 수 있습니다. 설치 도우미는 이 값을 받아 `web/.env` 파일을 자동으로 만듭니다.

1 기본 정보
2 집단 이름
3 Firebase
4 Cloudflare
5 실행
프로젝트 설정 > 일반 > 내 앱 > 웹 앱 > SDK 설정 및 구성 > 구성(Config)에 표시된 값만 옮겨 적습니다.

처음이면 여기부터

https://console.firebase.google.com/
1구글에서 Firebase 콘솔 또는 Firebase console을 검색해도 됩니다.
2프로젝트 추가를 누르고 Firestore Database를 만듭니다.
3프로젝트 설정의 일반 탭에서 웹 앱을 추가합니다.
4Config 코드에 있는 `apiKey`, `projectId`, `appId` 등의 값을 복사합니다.
5서비스 계정 탭에서 비공개 키 JSON 파일을 내려받아 기본 정보 화면에 선택합니다.
서비스 계정 JSON은 비밀번호처럼 다룹니다. GitHub나 카페 글에 첨부하지 않습니다.
Cloudflare 배포 설정 화면

Cloudflare는 Worker와 Pages로 나눠 배포

Cloudflare의 Workers & Pages 메뉴 안에서 두 가지가 사용됩니다. Worker는 PIN 로그인용 서버이고, Pages는 성원들이 보는 웹사이트입니다.

1 기본 정보
2 집단 이름
3 Firebase
4 Cloudflare
5 실행
먼저 Cloudflare 계정을 만들고 대시보드의 Workers & Pages 메뉴를 찾습니다. 설치 도우미에서는 이름만 정하면 됩니다.
SecretFIREBASE_SERVICE_ACCOUNT
APIPIN 로그인 처리
Pages웹 화면 배포

처음이면 여기부터

https://dash.cloudflare.com/
1구글에서 Cloudflare dashboard 또는 Cloudflare 대시보드를 검색해도 됩니다.
2로그인 후 Workers & Pages 메뉴를 찾습니다.
3Worker는 서버 작업, Pages는 웹 화면이라는 점만 구분하면 됩니다.
4설치 도우미가 `wrangler.toml`의 Worker 이름과 Firebase Project ID를 채웁니다.
5서비스 계정 JSON은 Worker secret으로 등록됩니다.
wrangler secret put FIREBASE_SERVICE_ACCOUNT
6Worker를 먼저 배포하고, 그 주소를 웹 앱 환경값에 연결합니다.
7마지막으로 Pages에 성원용 화면을 배포합니다.
중요Cloudflare 로그인 승인 창은 사용자가 직접 확인해야 합니다.
