# 설치 도우미 재설계 계획 — "값을 찾아 적지 않는 설치"

상태: 문제 진단 + 재설계 계획 (대표 컨펌 전 — 실행 보류) · 작성·구현: Claude 단독 · 2026-09-06 · 대상: 배포본 `FSG_Distribution_Kit`
용어: **설치 도우미**(공식 명칭. "마법사" 표현 사용하지 않음)

---

## 0. 한 줄 결론
현재 설치가 어려운 이유는 코드가 아니라 **"사용자가 값을 7개 이상 찾아 타이핑하고, Node.js를 직접 깔고, 브라우저 로그인이 두 번 튀어나오고, 실패하면 영어 오류만 남는"** 흐름 때문이다.
재설계의 목표는 **"압축 풀기 → 설치.cmd 더블클릭 → 회중 이름·집단만 입력 → Google 로그인 → Cloudflare 로그인 → 키 1클릭 → 완료(주소·QR·PIN)"**, 타이핑 3항목 이하, Node 사전설치 없음, 15분 이내 첫 접속이다.

## 1. 현재 도우미 진단 (코드 기준 사실)
`scripts/install-helper-gui.ps1`(PowerShell WinForms, 6탭)와 `setup-from-csv.mjs`, `worker/`를 읽고 확인한 것.

| # | 막히는 지점 | 근거 | 영향 |
|---|---|---|---|
| 1 | **Node.js를 사용자가 직접 설치**해야 함 | `Get-Command node.exe` 확인만 하고 없으면 nodejs.org 안내 | 첫 관문에서 이탈. PATH 문제 빈발 |
| 2 | **Firebase 값 7개 수동 타이핑** (Project ID, apiKey, authDomain, storageBucket, messagingSenderId, appId) + 서비스 계정 JSON | 탭 2·4에 텍스트박스 | 오타·다른 프로젝트 값 혼입 → 흰 화면 |
| 3 | **Firestore DB 생성, Firebase Auth 켜기**는 도우미 밖(콘솔 수동) | 도우미에 단계 없음 | 빠뜨리면 데이터 못 읽음/로그인 불가 |
| 4 | **Worker 시크릿 `FIREBASE_SERVICE_ACCOUNT`를 도우미가 설정하지 않음** | `worker/src/index.js` 23·95행이 이 시크릿을 요구, 도우미엔 `wrangler secret put` 없음 | **설치해도 감독자 로그인 불가** (`SERVICE_ACCOUNT_NOT_CONFIGURED`). 확실한 결함 |
| 5 | **Worker 주소를 배포 전에 미리 알아야 함** (`YOUR_SUBDOMAIN` 자리표시) | 탭 5 `txtWorkerUrl` 기본값 | 초보자는 자기 workers.dev 서브도메인을 모름 |
| 6 | **CLI 로그인 2회(firebase-tools, wrangler)가 실행 중 갑자기 브라우저로 튀어나옴** | `npx firebase-tools deploy`, `npx wrangler deploy` | 무슨 창인지 몰라 닫아버림 → 실패 |
| 7 | **`npm install` 2회(약 200MB) + `vite build`를 설치 PC에서 수행** | 탭 6 체크박스, web deps(vite/firebase/tiptap/pdfjs/xlsx) | 느리고 가정용 네트워크에서 자주 실패. Node 필수 원인 |
| 8 | **Pages 프로젝트 미생성** 상태에서 첫 `pages deploy` | 사전 `pages project create` 없음 | 대화형 프롬프트가 뜨는데 출력 리다이렉트 상태라 **멈춤(hang)** |
| 9 | 한 버튼("준비 파일 만들기")에 전부 묶임, **원문 영어 오류만 표시**, 재실행 시 처음부터 | `Run-ProcessLog` throw → MessageBox | 어디서 왜 실패했는지 모름 |
| 10 | Windows 전용(WinForms) | — | Mac 사용자 설치 불가 |
| 11 | 탭 구조라 **필수 단계를 건너뛸 수 있음**, 값 찾는 위치 링크 없음 | 검증은 마지막에만 | 순서 혼란 |

> 요약: 사용자가 해야 할 "찾기·타이핑·판단"이 너무 많고, 도우미가 **자동으로 할 수 있는 일(값 조회·생성·시크릿 설정·URL 캡처)을 사람에게 떠넘기고** 있다.

## 2. 설계 원칙
1. **값을 찾아 적지 않는다** — 로그인만 하면 도우미가 조회·생성한다.
2. **설치 프로그램을 먼저 깔지 않는다** — 필요한 실행환경은 배포본에 동봉한다.
3. **한 화면에 한 가지**, 상태는 초록/빨강, 실패하면 **한국어 원인 + 해결 버튼**.
4. **재실행 = 이어하기** — 단계 상태를 저장하고 실패 지점부터 다시.
5. **첫 접속까지 책임** — 완료 화면에 주소·QR·기본 PIN·다음 할 일까지.
6. 비밀(서비스 계정 키)은 PC 밖으로 나가지 않는다(Worker 시크릿 업로드 제외).

## 3. 구조적으로 바꾸는 세 가지 (효과 큰 순)

### 레버 A. 런타임 설정(config.json) + 미리 빌드된 dist 동봉  ★ 최우선
- 지금은 Firebase 값을 **빌드 시점** `import.meta.env.VITE_*`로 굽는다(`web/src/firebase.js` 6~24행). 그래서 회중마다 설치 PC에서 `npm install` + `vite build`를 해야 한다.
- 바꿈: `firebase.js`가 시작 시 **`/config.json`을 fetch**(또는 `window.__FSG_CONFIG__`)해서 읽도록 한다. 항목: apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId, workerUrl.
- 효과: 배포본에 **빌드 완료된 `dist/`를 동봉** → 설치자는 `dist/config.json` 한 파일만 생성하면 끝. **npm install·vite build·Node 필요성의 대부분이 사라진다.** 업데이트도 dist 교체만으로 끝.
- 주의: apiKey 등 웹 설정값은 원래 공개값이라 config.json 노출은 문제없음(보안은 Firestore 규칙이 담당).

### 레버 B. CLI 자동 프로비저닝 — 사용자는 "로그인"만
- **Google**: `firebase login` 1회 후 도우미가 순서대로 실행
  - 프로젝트: `firebase projects:create <slug>` (또는 기존 목록에서 선택)
  - Firestore: `firebase firestore:databases:create "(default)" --location asia-northeast3` *(가용성 검증 필요, 불가 시 딥링크 폴백)*
  - 웹앱 등록: `firebase apps:create WEB "<회중명>"`
  - 설정값 6개 자동 획득: `firebase apps:sdkconfig WEB <appId>` → **타이핑 0**
  - 규칙 배포: `firebase deploy --only firestore:rules,firestore:indexes`
- **Firebase Auth 켜기**: CLI 없음 → **딥링크 1클릭** `https://console.firebase.google.com/project/<id>/authentication` → 사용자는 '시작하기'만 → 돌아와 [확인] (Identity Toolkit config API로 enabled 검증 가능한지 확인)
- **서비스 계정 키**: CLI로 발급 불가 → **딥링크 1클릭** `…/project/<id>/settings/serviceaccounts/adminsdk` → '새 비공개 키 생성' → 도우미가 **Downloads 폴더의 최신 `*-firebase-adminsdk-*.json`을 자동 감지해 제안**, `project_id` 일치 검증.
- **Cloudflare**: `wrangler login` 1회 후
  - `wrangler deploy` → **출력에서 Worker URL 파싱 → workerUrl 자동** (문제 5 해결)
  - `wrangler secret put FIREBASE_SERVICE_ACCOUNT` ← 키 파일 내용 (**문제 4 해결**)
  - `wrangler pages project create <slug> --production-branch main` → `wrangler pages deploy dist` (문제 8 해결)
- 이름은 회중명에서 **slug 자동 생성**(예 `fsg-dongducheon-south`), 수정 가능, 중복 시 `-2` 자동 제안.

### 레버 C. 실행환경 동봉(번들 런타임)
- 배포본에 `runtime/` 포함: **포터블 Node(node.exe, 약 30MB) + 사전 설치된 wrangler·firebase-tools**.
- 도우미와 배포 명령은 전부 `runtime/node`로 실행 → **사용자 PC에 Node 설치 불필요, npx 네트워크 다운로드 없음**(문제 1·6·7).
- 배포본 ZIP이 커짐(약 150~250MB) — 그러나 "한 번 받기" vs "여러 실패 지점" 트레이드오프에서 압도적 이득. (대안: 첫 실행 시 `runtime/`만 진행표시와 함께 내려받기)

> A+B+C 적용 시 사용자가 하는 일: **회중 이름·집단 입력, Google 로그인, Cloudflare 로그인, 키 생성 버튼 1회, 파일 선택 1회.** 나머지는 전부 자동.

## 4. UI 방식: 로컬 웹 화면 (권장)
- 도우미 = `runtime/node installer/server.mjs`가 `127.0.0.1:포트`로 작은 설치 페이지를 띄우고 기본 브라우저를 연다. `설치.cmd`(Windows) / `설치.command`(Mac)은 이걸 실행만.
- 장점: **한 화면 한 질문** 구성이 쉬움, 진행 상황 실시간(SSE), 앱과 같은 디자인 언어, **Windows·Mac 모두 지원**, Node를 어차피 동봉하므로 추가 비용 없음.
- 폴백: 최소 변경을 원하면 기존 WinForms를 아래 화면 순서로 개편해도 됨(단 Windows 전용).

## 7. 보안 원칙
- 서비스 계정 키는 `배포본/.secrets/`에만 복사(`.gitignore`), **Worker 시크릿 업로드 외 어디에도 전송 안 함**.
- 로그·설치결과 파일에서 `private_key`·PIN·개인정보 자동 마스킹.
- `config.json`엔 공개 웹 설정 + workerUrl만.
- 완료 화면에 "키 파일은 이 PC 밖으로 보내지 마세요" 1줄 안내.

## 8. 업데이트 경로도 단순해짐
- `업데이트.cmd`: GitHub 릴리스에서 새 `dist/`·`worker/`만 받아 교체 → `config.json`·`.secrets/`는 유지 → `wrangler deploy` + `pages deploy`만 재실행.
- 런타임 config 덕분에 **재프로비저닝·재빌드 없음**. (현재는 .env 보존·재빌드 필요)

## 9. 단계별 추진안 (Claude 직접 구현 · 단계마다 대표 컨펌 후 실행)

**Phase 1 — 즉효(가장 큰 마찰 제거)**
1. `firebase.js` 런타임 config.json 로딩 + 배포본에 빌드된 `dist/` 동봉 (레버 A)
2. 도우미가 **Worker 시크릿 설정**(`wrangler secret put`) + `wrangler deploy` 출력에서 **URL 자동 캡처** → config.json 자동 작성 (결함 4·5 수정)
3. **번들 런타임**(포터블 Node + wrangler + firebase-tools) 동봉, 모든 명령을 번들로 실행 (레버 C)
4. `pages project create` 선행 + 비대화형 플래그로 hang 제거 (결함 8)
5. 상태 파일·이어하기 + 한국어 오류 매핑표(6장)
6. 딥링크 버튼(Auth·SA 키·Firestore) + Downloads 키 자동 감지

**Phase 2 — 타이핑 0**
7. firebase CLI 자동 프로비저닝: 프로젝트 생성/선택 → Firestore 생성 → 웹앱 등록 → `apps:sdkconfig`로 값 자동 획득 (레버 B)

**Phase 3 — 경험 완성**
8. 로컬 웹 UI로 전환(한 화면 한 질문, 진행 체크리스트, QR, Mac 지원)
9. 설치결과 파일·진행자 모드(원격 지원 시 읽어줄 문구)

**Phase 4 — 선택(미래)**
10. 웹 설치기(다운로드 없이 브라우저에서 OAuth로 전부 프로비저닝) — UX 최상, 구축 비용 최대·OAuth 앱 필요
